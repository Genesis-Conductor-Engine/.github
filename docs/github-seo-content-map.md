## Objective

Turn the Genesis Conductor GitHub organization into a high-signal knowledge surface for:

1. human searchers evaluating federal AI, provenance, and acquisition-intelligence capabilities;
2. GitHub users discovering reusable AI workflow infrastructure;
3. LLM agents retrieving structured context for agency-integration, proposal, and capture workflows;
4. federal partners assessing whether Genesis Conductor is a trust layer for scientific, defense, and mission AI workflows.

## Search thesis

GitHub should not be treated only as a code archive. For Genesis Conductor, GitHub is a public knowledge graph with repos as indexed nodes and README files, topic tags, schemas, examples, and validation reports as retrieval surfaces.

The target ranking pattern is:

- org profile = canonical brand and capability map;
- core repos = executable or research artifacts;
- docs = human-readable search landing surfaces;
- schemas = machine-readable agent contracts;
- knowledge nodes = LLM retrieval anchors;
- examples = query and workflow evidence.

## README structure for each public repo

Each README should use this order:

1. one-line positioning statement;
2. problem statement;
3. what this repo contains;
4. quickstart or example;
5. inputs and outputs;
6. evidence and validation status;
7. relationship to Genesis Conductor;
8. keywords and query intents;
9. license and contact.

## LLM retrieval design

Every major repo should expose a small machine-readable node under `knowledge-nodes/` or link back to the org-level `knowledge-nodes/org-index.json`.

Node fields should include:

- `node_id`
- `node_type`
- `title`
- `summary`
- `operator_context`
- `intents`
- `entities`
- `query_triggers`
- `input_contract`
- `output_contract`

## Governance rules

- Do not claim grant awards, agency adoption, production deployment, or third-party validation unless directly evidenced.
- Prefer `designed for`, `supports`, `targets`, and `enables` over unverifiable deployment claims.
- Keep ORCID and publication anchors separate from commercial claims.
- Separate public marketing copy from internal/private technical details.
- Preserve `unknown` for unverified identifiers.
- Every evidence-bearing claim should link to a repository file, release, publication, DOI, or source URL.

## Definition of done

The org SEO integration is complete when:

1. profile README states the canonical positioning;
2. LLMS.txt exists at org root;
3. docs/github-seo-content-map.md exists;
4. schemas/knowledge-node.schema.json exists;
5. knowledge-nodes/org-index.json exists;
6. target public repos have keyword-dense descriptions and topics;
7. each major repo has a README with problem, contents, query intents, and evidence status;
8. no unverifiable federal, grant, or deployment claims are presented as fact.
